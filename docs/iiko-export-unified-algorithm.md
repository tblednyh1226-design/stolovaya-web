# Единый алгоритм выгрузки документов в iiko — проект для внедрения

Статус: НЕ ПРОВЕРЕН ПОЛНОСТЬЮ. Не включать в рабочую версию без тестирования. Дата аудита: 2026-11-05.

## Состояния
- Документ создан, ни разу не отправлен: «Выгрузить в iiko».
- Успешный ответ iiko для текущей версии: «Отправлено в iiko» (кнопка не запускает отправку).
- Изменение ранее выгруженного документа, увеличение source_version: «Повторно выгрузить в iiko».
- Успешный ответ iiko для новой версии: «Отправлено в iiko».
- Ошибка: оставить возможность ручной повторной отправки и показать конкретную ошибку.

## Правила
1. Отправка только по явному нажатию пользователя, без автоматической отправки при редактировании.
2. Повторная отправка передает актуальную версию как НОВЫЙ документ. Не искать, не сравнивать, не изменять и не удалять старый документ в iiko. Администратор самостоятельно удаляет старую версию в iiko.
3. Никаких предварительных проверок дублей в iiko. Ошибку непосредственно от API iiko показывать пользователю.
4. Статус «Отправлено» устанавливать только после успешного ответа API на отправку. Не считать найденный по номеру старый документ подтверждением отправки новой версии.
5. Фиксировать source_version, идентификатор попытки, время, ответ API и ошибку. Не допускать двух одновременных запросов по двойному нажатию.
6. Применять одинаково к реализации, утилизации, актам приготовления, перемещениям и остальным выгружаемым документам; не менять бизнес-логику их формирования.
7. Запрет редактирования закрытого периода сохраняется.

- stolovaya-iiko-utilization-draft v6: предварительный поиск старого документа и проверка по номеру удалены; фактическая повторная отправка не проверена.
- stolovaya-iiko-outbound v24: сохраняется поиск существующего документа и PUT-обновление; противоречит правилу №2.

- Риск: iiko может отклонить создание документа с тем же номером. Не скрывать ошибку API.

## Условия принятия
Для каждого вида документа: создание -> выгрузка -> статус «Отправлено» -> редактирование -> «Повторно выгрузить» -> успешная повторная выгрузка -> «Отправлено». Подтвердить по логам запросов, что не выполнялись предварительные GET/PUT/DELETE старого документа. Тестировать на согласованных тестовых данных, не выгружать реальные документы без разрешения.
